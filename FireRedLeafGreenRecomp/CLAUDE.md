# CLAUDE.md — FireRedRecomp

This game repo defers all rules to the platform core:

- `../gbarecomp/CLAUDE.md`     — execution contract
- `../gbarecomp/PRINCIPLES.md` — recomp principles
- `../gbarecomp/DEBUG.md`      — debug loop (RULE 0, RULE 0a, RULE 0b)
- `../gbarecomp/TCP.md`        — TCP debug protocol

## This repo hosts TWO games (FireRed + LeafGreen)

FireRed and LeafGreen are separate CMake targets (`FireRedRecomp`,
`LeafGreenRecomp`) built from one source tree via `add_gba_variant()` in
`CMakeLists.txt` — the Sonic3AndKnucklesRecomp pattern. Per-variant data
lives under `variants/<name>/` (game.toml + config/ + symbols/ +
generated/ + roms/). A fix in `src/` or the engine applies to both; per-
game facts live in each `variants/<name>/game.toml`.

## Build target

Builds against the **live `../gbarecomp` checkout on `main`** ("gbarecomp
as it is today"). Override with `-DGBARECOMP_ROOT=...` only if your layout
differs. Build with MSYS2 mingw64 + Ninja, invoked from PowerShell (the
Bash sandbox forces `TEMP=C:\Windows`, which breaks `cc1plus`).

## Showstopper: no interpreter, no game

**This game does not begin until the runtime is fully recompiler-
driven, including the BIOS.** See `../gbarecomp/PRINCIPLES.md`:
- "BIOS is sacred — and recompiled, not interpreted (SHOWSTOPPER)"
- "Interpreter is informative, never load-bearing (SHOWSTOPPER)"

## Game-specific rules

1. **The decomp is a reference, not an oracle.** `pret/pokefirered` is
   imported through `tools/import_pokefirered_symbols/` and only its
   symbol names, function boundaries, asset labels, and ROM-layout
   annotations enter this project. The decomp's C source, its build
   output, its toolchain — none of these may be linked, copied, or used
   as ground truth.
2. **mGBA is the oracle.** When the recompiled build differs from mGBA,
   mGBA is right unless we can show otherwise with a hardware test ROM.
   NanoBoyAdvance is a tiebreaker; never the primary.
3. **ROM hash gates everything.** The runner refuses to launch with an
   unknown ROM. Versions live in `variants/<name>/config/<region>.toml`.
   New versions are added by checksum, not by guessing. FireRed = USA rev0
   (`41cb23d8…`); LeafGreen = USA rev1 (`7862c67b…`).
4. **No FireRed special cases in the GBA core.** If FireRed exercises an
   obscure hardware corner, the fix lives in `gbarecomp/src/gba/` with a
   hardware-test citation, not behind `if (game == "firered")`.
5. **Generated C is never edited.** `variants/<name>/generated/*` is
   regenerated by `gba_recompile`. If output is wrong, fix the recompiler.
6. **Symbol typing is heuristic until proven.** The `.sym` seed has no
   text/data type field (see `symbols/README.md`). Treat the function
   set as a seed for the recompiler's discovery loop, not as truth.

## Validation milestones

In strict order, each measured (no eyeballing):

1. ROM hash verified.                                  ✅ (`41cb23d8…`)
2. Header / entrypoint decoded.
3. Reset / BIOS handoff matches oracle.
4. First executed game function identified.
5. First VBlank / IRQ path matches oracle.
6. First meaningful VRAM / OAM / PAL writes match oracle.
7. Title screen (GAME FREAK / intro) renders.
8. Input reaches game code; menu navigation works.
9. New-game path starts.
10. Save type (flash 1M) detected, save/load round-trips vs oracle.
